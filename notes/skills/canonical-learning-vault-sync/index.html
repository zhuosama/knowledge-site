学习资料 Canonical Vault 同步方法

Section titled “学习资料 Canonical Vault 同步方法”

从 WT 相图复习资料生成 · 未公开 项目中提炼的可复用同步护栏模式。

问题场景

Section titled “问题场景”

在多 agent（Codex/Claude/Hermes）共同维护学习资料的场景下，常见问题：

  1. Agent worktree ≠ 用户 vault：agent 在自己的工作目录生成文件，但用户通过 Obsidian 打开的是另一个路径
  2. 学习资料不在 Git 管理内：许多学习文件被 .gitignore 排除，Git commit/push 无法传递更新
  3. 两边各自更新：用户在真实 vault 中手动编辑，agent 在 worktree 中自动生成，两边都有新内容

Verify无CI/agent 完成后的验证
ToOneDriveworktree→vaultagent 生成新资料后
ToWorktreevault→worktree用户手动编辑后

步骤 5：完成标准定义

Section titled “步骤 5：完成标准定义”

Agent 生成学习资料后的完成标准不应是”worktree 中有文件”，而应是：

  1. ✅ 执行 Verify 模式，两边 hash 一致
  2. ✅ 或者执行 ToOneDrive 模式，将文件推送到真实 vault
  3. ❌ 仅在 worktree 中有文件 → 不算完成

反模式

Section titled “反模式”
  • ❌ 假设 Git 能覆盖所有学习资料 — 大部分学习文件是 ignored/untracked
  • ❌ 单向覆盖（cp -r worktree/ vault/）— 会丢失用户在真实 vault 中的手动编辑
  • ❌ 只检查 agent 自己的目录而不验证用户实际打开的路径
