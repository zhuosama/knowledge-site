机器人 Driver 分层排障

机器人 Driver 分层排障

Section titled “机器人 Driver 分层排障”

六步框架

Section titled “六步框架”

  1. 明确目标与安全边界
    说清想让什么发生，以及绝不能发生什么。例如：“只验证 TTS，不允许机器人移动。”

  2. 写出假设
    例如：“我怀疑手势名不符合 schema，因为 HTTP 与 RPC 都已成功。”

  3. 逐层隔离
    网络/IP/端口 → HTTP → JSON-RPC → MCP 工具参数 → Driver 插件 → DDS/机器人状态。

  4. 建立观测点
    记录请求 ID、请求体、HTTP 状态、顶层 error、嵌套工具结果、Driver 日志和实体姿态。

  5. 一次只改一个变量
    例如只把 high_wave 改成 high wave，再重复同一请求。

  6. 停止、回滚与复盘
    异常先保证物理安全；保留最后一个可工作请求，记录根因、证据和预防办法。

一次完整排障示例

Section titled “一次完整排障示例”

目标

Section titled “目标”

执行预定义 high wave，不允许底盘移动。

现象

Section titled “现象”

HTTP 200，外层 JSON-RPC 有 result，但内层提示未知手势 high_wave。

假设

Section titled “假设”

工具路由正常，错误来自手势字符串与 arm.list 不一致。

证据

Section titled “证据”
  • 端口可连接。
  • 请求 ID 得到对应响应。
  • 顶层没有 RPC error。
  • content[0].text 内含业务错误。
  • arm.list 返回 high wave，中间是空格。

单变量修正

Section titled “单变量修正”

仅将 gesture 改为 high wave，其余请求不变。成功后等待机器人稳定，再执行 arm.release。

预防

Section titled “预防”

动作前先调用 arm.list，不凭记忆拼手势。

面试口述

Section titled “面试口述”

我先确定目标和安全边界，再写假设。排查按网络、HTTP、JSON-RPC、MCP、Driver、DDS 和机器人状态逐层推进，每层设置观测点。一次只改一个变量，异常时先停止并保留证据，最后记录根因和预防措施。

自测

Section titled “自测”
  • 能把 connection refused、timeout、RPC error、业务 error 分到不同层。
  • 能给每层说出至少一个观测点。
  • 能用三分钟讲清上面的未知手势排障。
  • 能解释为什么“重试几次看看”不是默认策略。
