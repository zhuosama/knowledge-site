WSL 镜像网络模式会拆掉 VPN 的 TUN

WSL 镜像网络模式会拆掉 VPN 的 TUN

Section titled “WSL 镜像网络模式会拆掉 VPN 的 TUN”

症状：把手机插到电脑上想传个文件，一插就断网；关掉 VPN 客户端才恢复。 结论：WSL2 的 networkingMode=mirrored 会把宿主每一张网卡镜像进 WSL 虚拟机， 包括 VPN 的 Wintun TUN。插 USB 设备触发网络重枚举时，镜像绑定重建， VPN 的 TUN 网卡被连带删除 → VPN 独占的 metric=0 默认路由消失 → 整机断网。

⚠️ 本条是 Clash VPN 本机网络排障 里 曾经写错的「WSL 推荐解法」的更正。原始证据见 2026-09-10 证据 · 未公开。

为什么这是反直觉的

Section titled “为什么这是反直觉的”

mirrored 模式的宣传点是「WSL 与 Windows 共享网络命名空间，localhost 互通」， 用它确实能让 WSL 里直接访问 127.0.0.1:7890 的代理 —— 看起来完美。 但它同时把宿主的 VPN TUN 网卡也镜像走了，而 TUN 是独占默认路由的，一被拆就是全量断网。 ^[inferred] 代价不在「WSL 能不能上网」，而在「宿主的网络会不会被牵连」。这是评估镜像模式时最容易漏掉的一环。

第一步：确认你处在 mirrored 模式

Section titled “第一步：确认你处在 mirrored 模式”

mirrored 模式的特征指纹：WSL 里看得到宿主才有的那些网卡和 IP。

判据：如果 WSL 里出现了和 Windows 同 IP 的 ethX，或出现了 VPN 的 fake-ip 段（198.18.x），就是 mirrored。 NAT 模式下 WSL 只有一个 eth0（172.x.x.x），绝不会看见宿主的 WLAN IP。

Section titled “第二步：证明 TUN 是被谁删的（HCS / VmSwitch 事件）”

插一次手机，然后查系统事件与 HCS 状态。

关于 FSE Switch 是什么

Section titled “关于 FSE Switch 是什么”

^[extracted] fse.sys 的 CompanyName = Microsoft Corporation、FileDescription = Flow Steering Engine Driver。 它不是第三方软件，是 Windows 给镜像/流转向用的组件，所以「卸掉某个 App 就好了」这条路走不通。

❌ 错的

Section titled “❌ 错的”

在 .wslconfig 里设 networkingMode=mirrored。它会修好 WSL 的代理访问，代价是宿主 VPN 随时可能被拆。

✅ 对的：NAT 模式 + Allow LAN + 代理环境变量

Section titled “✅ 对的：NAT 模式 + Allow LAN + 代理环境变量”

生效（会关闭当前所有 WSL 会话）：

然后两步让 WSL 用上 Windows 的代理：

  1. VPN 客户端里开启 Allow LAN / 允许局域网 （否则内核只绑 127.0.0.1，WSL 从任何其它地址连都是 Connection refused）

  2. WSL 里按 NAT 网关地址配代理（网关 IP 每次重启会变，必须动态取）

^[inferred] 不想开 Allow LAN 的话，可在 Windows 侧用 netsh interface portproxy add v4tov4 listenaddress=0.0.0.0 listenport=17890 connectaddress=127.0.0.1 connectport=7890 做端口转发，这样 allow-lan: false 也能用；代价是需要管理员权限。

附带修法：用系统代理模式代替 TUN 模式

Section titled “附带修法：用系统代理模式代替 TUN 模式”

即使不用 WSL，能用系统代理就别用 TUN。 TUN 独占 metric=0 的默认路由，一旦网卡被拆就是全量断网；系统代理只是应用层设置，网卡怎么变都不影响直连回退。 见 Clash VPN 本机网络排障 第 4 步。

同一个「插手机断网」现象还有第二条独立成因，与 WSL 无关：

O+Connect（OPPO 跨屏互联）自带一个 LinkSwitchMgr，手机 USB 接入后 2 秒会主动把默认路由切到 USB 链路：

^[extracted] 日志位于 %APPDATA%\O+Connect\devicespace\<日期>_core-daemon.log。 若只需传文件，用 Windows 原生 MTP（手机 USB 模式选「传输文件」），并在不需要时退出 O+Connect。

排查时要同时验证这两条：mirrored 模式看 hcsdiag list + VmSwitch 事件； O+Connect 看 switch default route to link 日志。

自检清单

Section titled “自检清单”
  • 我用 ip -brief addr 确认过 WSL 里没有宿主网卡的 IP。
  • 我确认过 .wslconfig 里是 networkingMode=NAT。
  • 我插手机前后都在事件日志里看过 VmSwitch 的 NIC Delete 记录。
  • 我知道 VPN 的 TUN 网卡 GUID，并拿它跟被删的 NIC GUID 比对过。
  • 我没有把 FSE Switch 误认为第三方软件（它是 Microsoft 的 fse.sys）。
  • 我区分了「WSL 镜像」和「O+Connect LinkSwitch」两条独立成因。
  • 我改用系统代理模式或 Allow LAN 方案，而不是 mirrored。
