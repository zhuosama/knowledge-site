Phanthy Motus G1 面试现场通过版 Runbook

Phanthy Motus G1 面试现场通过版 Runbook

Section titled “Phanthy Motus G1 面试现场通过版 Runbook”

[!important] 当前主线 2026-07-28，HR 明确表示：对方提供电脑和考试流程，允许使用 AI；在 Phanthy Motus 上完成机器人“说话 + 动作”编排即通过。原 宇树 G1 实操面试学习路径 保留，但降级为扩展理解和故障兜底。

一句话理解这次面试

Section titled “一句话理解这次面试”

按对方给出的步骤，在提供的电脑和 Phanthy Motus 环境里，借助 AI 读懂现场工具或代码，让机器人先说一句话、再完成一个安全的上肢动作，并能判断是否真正执行成功。

这意味着：

  • 不需要在自己的电脑部署 WSL、Docker、ROS 2 或宇树 SDK。【HR 回复】
  • 可以现场用 AI 查 schema、解释代码和修正错误。【HR 回复】
  • 面试主目标是最小可复现闭环，不是现场推导规划控制算法。【HR 回复】
  • 现场流程、Dashboard 和实时工具 schema 高于任何旧笔记或仓库记忆。

学习边界

Section titled “学习边界”

必须会

Section titled “必须会”
能力为什么
读懂简单 JSON、schema 和参数类型工具或 Driver 会用字段说明“需要填什么”
先发现工具，再选择工具工具名称与参数可能随版本变化，不能靠背
编排 TTS 与一个上肢动作这是 HR 明确给出的通过目标
看软件返回，也看机器人实体软件成功不等于机器人已完成动作
使用 AI 但保留人工放行权AI 可能生成不存在的工具、字段或危险动作
出错后最小修改，不盲目重发真机可能延迟执行，重复动作有安全风险
诚实说明 AI 帮了什么能解释和验证才算自己的实践

知道即可

Section titled “知道即可”
  • Dashboard / AI → Agent Core → MCP Driver → ROS 2 / DDS / Unitree SDK → G1。
  • Agent Core Dashboard 的公开默认端口是 15678；官方 Driver 表中 unitree/g1 为 15701。
  • MCP 使用 initialize、tools/list、tools/call 完成握手、工具发现与工具调用。
  • Driver 会向 Agent Core 注册，Dashboard 可以显示并编排其工具。

暂停学习

Section titled “暂停学习”
  • 从零部署 WSL、Docker、ROS 2 和 G1 Driver。
  • 完整 C++、CMake、CI/CD。
  • 步态、动力学、MPC、轨迹优化和完整 MoveIt 体系。
  • 从零重写完整 Mock Server。
  • 深挖 DDS 和 Unitree SDK 内部实现。

这些内容仍有长期价值，但不是本轮通过条件。现有 Mock 只用于练习工具发现、参数和错误判断，不再作为训练主线。

三种可能的考试入口

Section titled “三种可能的考试入口”

入口 A：Dashboard Canvas 可视化编排

Section titled “入口 A：Dashboard Canvas 可视化编排”

官方 README 描述了在 Canvas 上放置传感器、执行器和 Agent Loop 的可视化流程。现场应：

  1. 按考试流程找到目标机器人或 Driver。
  2. 查看已出现的工具和字段。
  3. 找到与语音和上肢动作对应的节点。
  4. 按流程连接或配置。
  5. 分步运行，不一次释放全部动作。

不要背按钮位置；界面可能随版本变化。

入口 B：Dashboard 中使用 AI / Agent

Section titled “入口 B：Dashboard 中使用 AI / Agent”

让 AI 先读取当前工具和 schema，再给最小方案。你负责检查：

  • 工具是否真实存在。
  • 参数名、类型和枚举值是否来自当前 schema。
  • 是否偷偷加入行走、转身或大幅动作。
  • 是否把多个动作一次性发出。
  • 是否说明每一步如何判断成功。

入口 C：写或修改少量 Driver / Python 代码

Section titled “入口 C：写或修改少量 Driver / Python 代码”

“做 Driver 开发”可能要求在现有代码上做小改动，而不只是点 Canvas。稳妥顺序是：

  1. 找到最接近目标功能的现有插件或工具。
  2. 找到工具定义中的 inputSchema、action 和参数。
  3. 找到处理调用的 dispatch 或同类分发函数。
  4. 只做完成“说话 + 动作”所需的最小改动。
  5. 让 AI 输出小 diff，并逐行解释。
  6. 按考试流程运行与验证，不自行改部署环境。

为什么先仿照现有工具：现成代码已经体现当前仓库的注册、返回格式和错误处理，比让 AI 从空白生成可靠。

现场 SOP

Section titled “现场 SOP”

  1. 完整阅读考试流程
    先圈出目标、通过判据、允许使用的 AI、禁止项和最终提交方式。

  2. 确认安全和控制权
    问清现场负责人、遥控器或急停的位置、动作空间和异常时由谁处置。

  3. 识别当前入口
    判断是 Canvas、AI/Agent，还是修改少量 Driver 代码。

  4. 确认目标 Driver 和工具
    查看 Driver 是否在线、工具是否可见、schema 要求什么。不要先写动作。

  5. 先做 TTS
    TTS 没有位移，是验证整条调用链的低风险探针。

  6. 确认 TTS 成功
    同时看返回值和机器人是否真的发声。

  7. 选择单个小幅上肢动作
    只使用流程或当前 schema 明确提供的动作。

  8. 分步执行并等待稳定
    不把说话、多个动作和重复调用一次性堆在一起。

  9. 按现场 schema 收尾
    若流程提供 release、stop、finish 或其他收尾动作，使用其真实名称；若没有，不自行创造接口，按流程询问。

  10. 双重验收
    检查软件返回、日志和实体状态，并能向面试官复述调用顺序、成功判据和 AI 的作用。

最小排错树

Section titled “最小排错树”
现象优先判断最小动作
找不到目标工具Driver / 注册 / 当前页面检查 Driver 状态和考试流程，不改动作参数
schema 或参数报错字段名、类型、枚举值对照实时 schema，一次只修一个字段
TTS 成功、动作失败动作工具或机器人姿态单独检查动作调用，不重发 TTS 和整个流程
软件成功、机器人没动作真机状态或控制权抬头看实体、查日志、问现场负责人，不反复发送
AI 给出不存在的工具AI 幻觉要求它引用当前 schema；无法引用就拒绝方案
出现意外运动物理安全停手、不靠近、不进入动作范围，交由现场负责人处置

七个训练日

Section titled “七个训练日”

7 月 28 日：读 schema

Section titled “7 月 28 日：读 schema”
  • 产出：手写一份“工具名—action—必填参数—成功字段”表。
  • 通过门槛：能说明为什么工具名称不能死背。

7 月 29 日：TTS 最小闭环

Section titled “7 月 29 日：TTS 最小闭环”
  • 产出：在现有 Mock 或纸面 schema 中完成一次 TTS 请求分析。
  • 通过门槛：能说出输入、返回和实体三个成功证据。

7 月 30 日：动作与收尾

Section titled “7 月 30 日：动作与收尾”
  • 产出：一份“动作前—动作中—稳定后”安全检查表。
  • 通过门槛：知道收尾名称必须来自现场 schema，而不是凭记忆写 release。

7 月 31 日：三种入口

Section titled “7 月 31 日：三种入口”
  • 产出：分别写出 Canvas、AI 调用和小代码修改的执行顺序。
  • 通过门槛：看到界面后能判断自己处在哪一种入口。

8 月 1 日：AI Prompt 演练

Section titled “8 月 1 日：AI Prompt 演练”
  • 产出：用四张 Prompt 卡完成一次工具盘点、最小方案和错误修正。
  • 通过门槛：能识别 AI 发明的工具或危险动作。

8 月 2 日：排错与安全

Section titled “8 月 2 日：排错与安全”
  • 产出：分别演练工具不可见、参数错误、软件成功但实体未动。
  • 通过门槛：每种错误都先归层，只改一个变量。

8 月 3 日：完整模拟

Section titled “8 月 3 日：完整模拟”
  • 产出：走完“流程—安全—工具—TTS—动作—收尾—验收—口述”。
  • 通过门槛：无安全否决项，能解释每一步和 AI 的贡献。

8 月 4 日：考前复习日

Section titled “8 月 4 日：考前复习日”
  • 只复习现场 SOP、四张 Prompt 卡和排错树。
  • 不安装环境、不扩展技术栈、不重写代码，保证睡眠。

面试通过自检

Section titled “面试通过自检”
  • 我先读了流程和实时 schema。
  • 我没有主动测试行走或整机移动。
  • TTS 真正发声，且我能指出软件证据。
  • 只执行了一个流程允许的上肢动作。
  • 我按现场真实接口完成收尾或向负责人确认。
  • 异常时没有重发或进入动作范围。
  • 我能解释 AI 提供了什么、自己验证了什么。
  • 我知道“完成即通过”还要确认是通过本轮还是直接录用。

面试当天 15 分钟热身

Section titled “面试当天 15 分钟热身”
  • 3 分钟：复述十步现场 SOP。
  • 3 分钟：复述排错树。
  • 3 分钟：读一遍 Prompt 1 和 Prompt 2。
  • 3 分钟：练习“我先看实时 schema，不猜接口”。
  • 3 分钟：提醒自己目标只有“一句话 + 一个动作 + 可解释的成功证据”。

2026-08-06 实测复盘（面试后追加）

Section titled “2026-08-06 实测复盘（面试后追加）”

真机面试后的三条教训，写入后续任何现场准备：

  1. 先读现场所有可见提示：电脑旁的纸条/说明卡可能直接告诉你”哪些不用做”（本次纸条写”机器人操控先不用做”）。进场第一件事：扫一遍桌面、屏幕、文档。
  2. 题目语义不明时尽早换思路或问面试官：第 7 题”在控制页面的 Actuator 中新增卡片”，UI 找不到入口时，应更早意识到是改代码/配置注册卡片，而不是反复找界面按钮。识别”找不到 UI 入口”= “要动代码”的信号，最多花 2 分钟确认，不耗 20 分钟。
  3. 时间分配：核心题（创建+运行验证）应留足运行和排错时间；环境题（1-6）快速通过即可。
