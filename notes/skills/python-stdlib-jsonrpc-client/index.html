用 Python 标准库编写 JSON-RPC 客户端

用 Python 标准库编写 JSON-RPC 客户端

Section titled “用 Python 标准库编写 JSON-RPC 客户端”

需要的最小语法

Section titled “需要的最小语法”

面试任务只需要掌握：

  • dict / list：表示请求和响应。
  • 函数：把一次 RPC 调用封装起来。
  • if：区分 result、error 和工具业务错误。
  • try / except：区分 HTTP、连接、超时和 JSON 解析异常。
  • json.dumps / json.loads：Python 对象与 JSON 文本互转。
  • encode / decode：文本与 HTTP 传输字节互转。

最小可解释 Client

Section titled “最小可解释 Client”

每一步为什么存在

Section titled “每一步为什么存在”
  1. dict 保留 JSON 的层次结构，比手拼字符串可靠。
  2. json.dumps 返回 str，HTTP 请求体需要 bytes，所以要 encode("utf-8")。
  3. Content-Type: application/json 告诉服务端怎样解释请求体。
  4. timeout 防止客户端永久等待。
  5. 先看外层 error，再看 result.content[0].text，避免把业务失败当成功。
  6. 最后解析内层 text，因为工具返回被包装成 JSON 字符串。

常见错误

Section titled “常见错误”
  • 用字符串拼 JSON，导致引号或转义错误。
  • 忘记 encode，把 str 当 HTTP body。
  • 不设 timeout，服务端卡住时客户端无限等待。
  • 每个请求都使用相同 id，日志难以关联。
  • 只解析外层 JSON，没检查嵌套业务 error。
  • 捕获所有异常后只输出“失败”，丢失错误层次。

面试口述

Section titled “面试口述”

我用 dict 构造 JSON-RPC 请求，通过 json.dumps 和 UTF-8 encode 变成 HTTP body，用 urllib POST 到 /mcp。客户端带递增 id 和明确 timeout。响应先解析外层 JSON-RPC，检查顶层 error，再解析 result.content[0].text 的工具结果，这样能区分协议错误和业务错误。

自测

Section titled “自测”
  • 能解释 dumps、loads、encode、decode 的方向。
  • 能不用复制写出 rpc_call 的请求体。
  • 能故意改错端口并识别 connection refused。
  • 能用不存在的 gesture 触发并识别工具业务错误。
  • 随机抽取十行代码都能解释其输入、输出和失败方式。
