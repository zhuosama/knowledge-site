桌面 GUI 工程化 — tkinter/ttk 六条接线铁律

桌面 GUI 工程化 — tkinter/ttk 六条接线铁律

Section titled “桌面 GUI 工程化 — tkinter/ttk 六条接线铁律”

用 tkinter/ttk 写内部工具（标注器、编辑器、看板）时，翻车的从来不是”好不好看”，而是四类接线错误： 事件绑定范围、尺寸依赖、焦点/快捷键冲突、异步写盘时序。下面六条来自实战：一个 ~1500 行的单文件标注工具 先做布局重构（r54），再由两个模型交叉 review 出 5 个功能性缺陷并修掉（r55）。

配套可复用代码：.agents/skills/desktop-gui-ttk/（SKILL.md + references/ttk-recipes.md + scripts/ttk_parts.py，224 行、python ttk_parts.py 可自检）。 视觉方向另见 本页所配的 frontend-design skill（anthropics/skills，Apache-2.0）。

1. 折叠分组用 grid_remove()，不要 destroy()

Section titled “1. 折叠分组用 grid_remove()，不要 destroy()”

折叠状态按分组持久化（prefs['ui']['sections'][title]），下次打开还是用户离开时的样子。 验证口径：全部折叠后容器 canvas.bbox('all')[3] 必须显著变小（实测 1146→166 px）。

2. 可滚动侧栏：不要用 bind_all 绑滚轮

Section titled “2. 可滚动侧栏：不要用 bind_all 绑滚轮”

最典型的错误写法（第一版就这么写的，被判”功能性回归”）：

内嵌 frame 和里面每个按钮都盖在 canvas 之上 → 指针一进子控件就触发 canvas 的 <Leave>， 滚轮在最需要的地方失效；而 bind_all 又劫持全局 → 模态框上滚轮会滚到身后的面板。正确做法：

两个必配的 <Configure>：内嵌 frame 变化 → 更新 scrollregion；canvas 变化 → itemconfigure(width=...) （漏掉后者，内层永远不按面板宽度回流）。

3. “适应窗口”必须现场重算

Section titled “3. “适应窗口”必须现场重算”

只在启动时算一次 fit、或 <Configure> 里”手动缩放期间直接 return”，都会让”适应”按钮撒谎 （实测修好后 fit 0.1465→0.1802）。手动缩放态下窗口变大要保持缩放比例，不要偷偷改。

4. 多行文本要兼容 Entry 语义，并防丢字

Section titled “4. 多行文本要兼容 Entry 语义，并防丢字”

tk.Text 不认 insert(0, s) / delete(0, 'end')：共享的同步助手 for w in (combos..., text): w.delete(0, 'end') 会直接崩 TclError: bad text index "0"。 适配 + 三个易漏行为：

  • 本地撤销：undo=True + 控件级 <Control-z> → edit_undo() 并 return 'break'（否则触发全局撤销）
  • Return = 应用 / Shift+Return = 换行
  • 防抖 + 失焦 flush + 切行取消：<KeyRelease> 500ms 防抖；<FocusOut> 立即落盘； _sync_fields() 第一行 after_cancel(_tjob) —— 否则定时器在你切换条目后触发，把上一行的文本写进新行

5. 悬浮提示要读”鼠标下那一行”

Section titled “5. 悬浮提示要读”鼠标下那一行””

按 <Enter> + selection() 会在任何”没先选中就悬停”的场景显示错误内容。改为 <Motion> + ~450ms 延迟 + tree.identify_row(ev.y)，并按屏幕边界钳制坐标 + lift()/-topmost，<Leave> 时销毁。

6. 模态与分割条

Section titled “6. 模态与分割条”
  • wait_visibility() 之后再 grab_set()（未映射时 grab 是空操作）。
  • ttk.PanedWindow.add(child, weight=...) —— 当前 Tk 不接受 minsize=（TclError: unknown option "-minsize"）。
  • 分割条位置要在窗口映射后恢复，且失败要重试：winfo_width() < 100 时返回 False 让调用方再试 （≤6 次 ×250ms）。把”已完成”标志提前置位（第一版的写法）会导致第一次空操作后永久不再恢复。

审查清单（交付前逐条过）

Section titled “审查清单（交付前逐条过）”
  • minsize() 下每个按钮都够得着（会不会有一块固定宽度面板把关键控件挤出屏幕）
  • 滚轮在子控件上有效；模态框不被劫持；没有 bind_all
  • 「适应 / 1:1 / ±」在任何窗口尺寸与手动缩放后都正确
  • 文本：输入 → 失焦 → 落盘；切换行不会把上一行文本写进新行
  • Ctrl+S/Z/Y、Delete、Esc、Return 在文本框内与列表上的行为不同且不互相污染
  • 悬浮提示按鼠标行取内容、<Leave> 销毁
  • 模态：wait_visibility → grab_set；其滚轮不滚父面板
  • 关窗保存几何/分割条；挂起的 after 任务被取消
  • 125%/150% DPI 与 1366×768 下不重叠、不裁切

双模型 review 工作流（性价比最高的一步）

Section titled “双模型 review 工作流（性价比最高的一步）”

两轮都要求输出：严重度 + 函数/行号、可直接 str.replace 的旧→新代码块、最后一行 RELEASE: 可以发布|不可发布。第 2 轮确实抓出了第 1 轮因果说反的一处并补了 4 个真缺陷。 坑：带文件读取工具的推理模型读 1500 行文件会 >1700s 超时；把关键 ~200 行内联进 prompt + --no-tools → 17s 出结果（且要在首行明写”禁止调用工具”，否则模型会输出 tool_call 文本）。

验证方式：合成事件断言，不靠肉眼

Section titled “验证方式：合成事件断言，不靠肉眼”

用 duck-typed 事件对象（带 x/y/delta/num/state）+ event_generate 就能把整个 GUI 纳入回归测试， 本页所有修复都是这样验证的。
