YOLO 训练调优与故障排查

YOLO 训练调优与故障排查

Section titled “YOLO 训练调优与故障排查”

摘要

Section titled “摘要”

本文给出一套新手可执行的排查顺序：先验证数据，再确认基线，然后只改一个变量，最后在目标硬件验证。大多数“模型不行”首先是标签、划分、分辨率或指标解释问题，而不是需要立刻改网络。^[inferred]

1. 最有效的排查顺序

Section titled “1. 最有效的排查顺序”

“小样本过拟合测试”是指拿 10–30 张图训练足够久，确认模型能把训练集学到很高精度。如果连这一步都做不到，应优先怀疑数据或训练链路，而不是泛化能力。^[inferred]

2. 常见问题与解决办法

Section titled “2. 常见问题与解决办法”
症状常见根因优先处理
训练提示找不到图/标签data.yaml 相对路径错误、目录名不匹配从 YAML 所在项目工作目录解析路径；检查图片与标签同名
框位置完全错把像素坐标当归一化坐标；把 xyxy 写成 xywh可视化标签；确保四个值在 0–1 且宽高为正
类别错位或报 class 超界类 ID 从 1 开始，或 names 数量不一致类 ID 从 0 开始且连续；核对 names
loss 正常下降但验证异常高train/val 有相邻视频帧、同一对象或增强副本按采集序列、场景、对象分组划分，去重
训练集很好、验证集差数据少、分布差异、模型过大、训练太久增数据；减小模型；early stopping；检查域偏移
Precision 高、Recall 低阈值高、漏标、小目标或类别覆盖不足降低推理 conf；补齐标注；提高分辨率；扩充难例
Recall 高、Precision 低阈值低、背景负样本少、相似类别混淆提高 conf；加入 hard negatives；复核类定义
小目标几乎检测不到输入缩放后目标只有几像素、数据不够、框不一致增大 imgsz、切片训练/推理、保留高分辨率、增加小目标样本
密集目标互相丢失NMS 抑制、遮挡、分辨率不足调整 IoU 阈值；提高分辨率；尝试切片/更合适任务头
显存不足 OOMbatch、imgsz、模型过大依次减 batch、imgsz、模型；关闭 cache；使用 AMP
Windows DataLoader 卡住多进程 worker/入口保护问题先设 workers=0；脚本使用 if __name__ == "__main__":
指标波动很大验证集太小、类别样本不均、随机性扩大/固定验证集；设 seed；做多次运行或交叉验证
导出模型与 .pt 差异大前后处理、精度或动态尺寸不一致用固定样本做逐级等价性测试；核对 letterbox、RGB、NMS

3. 数据质量比调参更优先

Section titled “3. 数据质量比调参更优先”

标注一致性

Section titled “标注一致性”

为每个类别写清楚：什么必须标、什么不标、被遮挡到什么程度仍标、框要贴紧可见区域还是完整推测区域。团队成员标准不一致会制造不可学习的噪声。^[inferred]

漏标的破坏性

Section titled “漏标的破坏性”

若图中真实目标未标，训练器可能把它当背景，模型会同时收到“识别它”和“忽略它”的冲突信号。尤其是密集场景，要系统检查漏标。

数据量与多样性

Section titled “数据量与多样性”

不要只追求图片数量。覆盖相机、角度、距离、背景、天气、光照、遮挡、模糊和设备差异。生产环境中最难的条件应进入验证/测试集。

类别不平衡

Section titled “类别不平衡”
  • 先统计每类图片数与实例数。
  • 补采稀有类别和混淆类别。
  • 适度过采样或针对性增强，但避免复制导致泄漏。
  • 查看逐类 AP，而不是只看总 mAP。
  • 若两个类别肉眼都难以稳定区分，先重新定义标签体系。

4. 过拟合与欠拟合

Section titled “4. 过拟合与欠拟合”
状态曲线特征对策
过拟合train loss 继续下降，val mAP 停滞或变差更多真实数据、增强、较小模型、early stopping、减少 epoch
欠拟合train/val 都差，训练损失仍高训练更久、检查学习率、提高模型容量/分辨率、检查标签
数据域偏移离线 val 好，现场差收集现场数据；按现场条件建独立 test；重新微调

增强不是越强越好。颜色变化不能改变类别语义；上下翻转在街景中通常不自然；严重 Mosaic 可能与真实部署分布不符。每次应可视化增强后的样本。^[inferred]

5. 小目标专项

Section titled “5. 小目标专项”
  1. 提高 imgsz：例如 640 → 960/1280，但显存和计算量近似随像素数增长。
  2. 切片（tiling）：把超大图切成重叠小块训练或推理，再合并框；遥感和表面缺陷常有效。
  3. 保留原始细节：避免上传、转码或预处理先把小目标压没。
  4. 补充近景与难例：让模型看到不同尺寸和背景。
  5. 检查检测层：高级场景可使用更高分辨率的 P2 检测层，但属于结构改动，需要与简单基线对照。
  6. 考虑 OBB/Segmentation：细长、旋转或轮廓型目标可能不适合水平框。

6. 实用训练参数

Section titled “6. 实用训练参数”

具体默认值会随 Ultralytics 版本变化，运行前以当前 配置参考 为准。

学习率

Section titled “学习率”
  • loss 发散、出现 NaN：降低学习率并检查坏数据。
  • 收敛非常慢：可能学习率过低，也可能数据/冻结层有问题。
  • 不要同时更改学习率、batch、增强和模型尺寸，否则无法知道哪个变量起作用。
  • batch 变化会改变优化噪声和有效训练行为，调参记录中必须注明。

数据增强

Section titled “数据增强”
  • Mosaic：组合多图，增加尺度与上下文变化，对小目标可能有帮助。
  • MixUp：图像混合，可能增强泛化，但标签语义复杂时谨慎。
  • HSV/亮度变化：覆盖照明差异，但不能制造不真实颜色。
  • 几何增强：平移、缩放、翻转、透视应符合真实相机和物理场景。

Anchor 设置

Section titled “Anchor 设置”

YOLOv8 检测头是 anchor-free，通常无需手动设置 anchor。修改 anchor 的教程多数面向 YOLOv2–v5 等 anchor-based 实现；在那些版本中可重新聚类或使用 AutoAnchor。先确认版本机制，再采取动作。

预训练与冻结

Section titled “预训练与冻结”
  • 小数据集通常从 COCO 预训练权重开始。
  • 领域与 COCO 差异很大时，冻结主干只适合作为快速实验；最终通常应尝试全量微调。
  • 若新类别与 COCO 同名，也不能假设模型已经适配你的摄像头和场景。

7. 如何设计一次可信的调优实验

Section titled “7. 如何设计一次可信的调优实验”
  1. 固定 train/val/test 划分和随机种子。
  2. 保存基线配置、版本、权重、GPU 和指标。
  3. 每次只改变一个主要因素。
  4. 不仅记录 mAP，还记录逐类 AP、延迟、显存、典型失败图。
  5. 选择阈值时依据业务成本：漏检和误检哪个更贵。
  6. 最终只在 test 集做少量确认，不能反复用 test 调参。

8. 部署性能调优

Section titled “8. 部署性能调优”
  • 先测 PyTorch 基线，再测 ONNX/TensorRT/OpenVINO。
  • 区分冷启动、warm-up 后延迟、平均延迟和 P95/P99 延迟。
  • batch=1 更接近实时摄像头；大 batch 吞吐高但单帧等待可能更久。
  • FP16 通常是 NVIDIA GPU 上低风险的第一步；INT8 必须用代表性数据校准并复测精度。
  • 性能测量应包含解码、resize/letterbox、数据拷贝、推理、NMS/后处理和渲染。
  • 边缘设备还要观察功耗、温度降频和长时间稳定性。
