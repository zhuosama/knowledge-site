Clash VPN 本机网络排障

Section titled “Clash VPN 本机网络排障”

[!warning] 定位说明（2026-09-10 补充） 本文只解决传输层问题：代理内核、系统代理、TUN 权限、DNS 死锁、WSL 边界。 如果用户的真实痛点是 Codex / Claude Code 等 AI 客户端报“网络错误”， 真正的主因往往是用量配额而非网络，请先读 Codex 用量超限与网络故障的鉴别， 再用本文的流程排查剩下那部分真网络问题。

^[inferred] 本文是“代理为什么不通”的前置知识，不是“客户端为何报错”的答案。

本文回答一个问题：「装了好几个 VPN，一个都用不了」时，按什么顺序查。 完整实测证据见 2026-09-10 诊断证据 · 未公开； 本机当前实际客户端/端口/订阅清单见 本机 VPN 与网络客户端实测清单。

Section titled “第 0 步：先确认「你在哪一侧」”

违反此步会整段查错方向。本机 Agent 的 Bash 实际跑在 WSL2 里，而用户说的「本机」是 Windows。

第 7 步：WSL / 调用方边界

Section titled “第 7 步：WSL / 调用方边界”

Windows 能翻墙 ≠ WSL 里的工具能翻墙。

两个原因同时成立才会 refused：

  1. WSL2 默认 NAT 模式：WSL 有独立网络命名空间，127.0.0.1 不是 Windows 的 127.0.0.1；
  2. Clash allow-lan: false：只绑 127.0.0.1，拒绝任何来自 WSL 网段的连接。

❌ 反面教材：不要用 networkingMode=mirrored

Section titled “❌ 反面教材：不要用 networkingMode=mirrored”

[!danger] 2026-09-10 实测回滚 —— 本条曾被写成「推荐修复」，是错的 mirrored 模式确实能让 WSL 内 127.0.0.1:7890 直达 Clash， 但代价是：只要宿主网络发生任何重枚举（插拔 USB 手机、切 WiFi），VPN 的 TUN 网卡会被删除，整机断网。 详见 WSL 镜像网络模式会拆掉 VPN 的 TUN。

机制：mirrored 模式下 WSL2 通过 FSE Switch（Flow Steering Engine） 把宿主每一张网卡镜像进 WSL 虚拟机，其中包含 VPN 客户端的 Wintun TUN。

^[extracted] 复现方式：起一个后台记录器监控「TUN 网卡 / 默认路由 / 连通性」，插入手机即可看到 TUN 在同一个 700ms 窗口内消失。

自检清单

Section titled “自检清单”
  • 我先确认了故障发生在 Windows 还是 WSL。
  • 我用 -Proxy 显式测过一次，分清了「代理不通」和「没人用代理」。
  • 我读了内核真实的 -d 目录，而不是默认路径。
  • 我看了 ProxyEnable，并知道多个客户端会互相关掉它。
  • 我用规则条数判断内核吃的是真订阅还是错误占位页。
  • 遇到 dns resolve failed 时，我先 nslookup 了节点域名，确认不是节点死。
  • 我知道 proxy-server-nameserver 必须是明文 IP。
  • TUN 报 Access is denied 时我知道要开 Service Mode 而不是重装。
  • 我核对了订阅到期时间。
  • 我检查了 WSL 侧到底能不能连到那个端口。
