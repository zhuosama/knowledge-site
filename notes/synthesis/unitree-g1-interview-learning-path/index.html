宇树 G1 实操面试学习路径

宇树 G1 实操面试学习路径

Section titled “宇树 G1 实操面试学习路径”

[!important] 2026-07-28 范围更新 HR 已确认对方提供电脑和操作流程、允许使用 AI，完成 Phanthy Motus 上的“说话 + 动作”编排即可通过。本页保留为扩展准备；当前应优先学习 Phanthy Motus G1 面试现场通过版 Runbook。岗位真实性与工作内容疑问见 第四范式 G1 规控实习岗位可靠性核查。

最终目标

Section titled “最终目标”

面试前不追求掌握整套人形机器人开发，而要做到：

  1. 安全完成“确认环境 → 查工具 → TTS → 单个上肢动作 → release”。
  2. 90 秒解释 Client → Driver → ROS 2/rclpy → DDS/Unitree SDK → G1。
  3. 区分参数错误、端口不通、超时和实体异常。
  4. 诚实区分亲手实践、AI 辅助和源码理解。

先修顺序

Section titled “先修顺序”

按下面顺序读，不要一开始钻 ROS 2 或 C++：

  1. HTTP、JSON-RPC 与 MCP 分层
  2. Phanthy Motus G1 HTTP MCP 接口速查
  3. 用 Python 标准库编写 JSON-RPC 客户端
  4. Linux 机器人网络与端口排查
  5. 宇树 G1 真机软件链路
  6. 机器人 Driver 分层排障
  7. 人形机器人现场安全操作
  8. 协议 Mock 与真实机器人的边界

每日固定节奏

Section titled “每日固定节奏”

每天约四小时：

  • 45 分钟：概念与语法。
  • 90 分钟：亲手敲代码和运行。
  • 45 分钟：读准备资料或固定版本源码。
  • 30 分钟：脱离笔记口述。
  • 30 分钟：让 Claude 追问、审查风险并复盘。

^[inferred] Claude 的角色是第二审查者和面试官，不替代亲手敲核心代码；只有能独立复现并逐行解释的内容，才算自己的实操能力。

九天看板

Section titled “九天看板”

Day 1｜7 月 27 日：环境与全链路

Section titled “Day 1｜7 月 27 日：环境与全链路”
  • Windows 或 WSL 中能运行 python3 --version 与 curl --version。
  • 画出 Client 到 G1 的完整链路。
  • 区分 Agent Core 15678 与 Driver 15701。
  • 60 秒解释 Mock 覆盖到哪里。

通过标准：能调通 Mock 的 tools/list，且没有把 Mock 说成真机仿真。

Day 2｜7 月 28 日：Python、JSON、HTTP

Section titled “Day 2｜7 月 28 日：Python、JSON、HTTP”
  • 手写嵌套 dict / list。
  • 解释 dumps、loads、encode、decode。
  • 手写 initialize、tools/list、tools/call 请求。
  • 解释外层 JSON 与 content[].text 内层 JSON。

通过标准：不看参考写出三个请求，并解释每个字段。

Day 3｜7 月 29 日：最小 Client

Section titled “Day 3｜7 月 29 日：最小 Client”
  • 亲手完成带 URL、timeout、递增 ID 的 Client。
  • 输出明确的 HTTP、连接、超时、RPC 和工具业务错误。
  • 完成一次 tts.speak。
  • 随机抽十行代码逐行解释。

通过标准：不借助 AI 完成一次 TTS 请求并解释结果。

Day 4｜7 月 30 日：精确 HTTP Mock

Section titled “Day 4｜7 月 30 日：精确 HTTP Mock”
  • 实现 POST /mcp。
  • 实现 initialize、tools/list、tools/call。
  • 实现 tts、arm、loco 的协议级分发。
  • 让成功工具结果进入 result.content[].text。

通过标准：未知手势返回业务错误，非法 JSON 返回 -32700，并能解释入口到分发的代码。

Day 5｜7 月 31 日：故障与日志

Section titled “Day 5｜7 月 31 日：故障与日志”
  • 触发非法 JSON。
  • 触发未知 method / tool。
  • 触发未知 gesture。
  • 触发服务端异常、timeout、错误端口。
  • 每次按六步框架填写排障日志。

通过标准：看到现象后先归层，不盲目重试。

Day 6｜8 月 1 日：固定版本源码与真实性

Section titled “Day 6｜8 月 1 日：固定版本源码与真实性”
  • 追踪 main.py → device.py → tts/arm/loco。
  • 找到网卡参数进入通信初始化的位置。
  • 完成“亲手 / AI 辅助 / 只理解”矩阵。
  • 90 秒解释真机链路和 Mock 缺失层。

通过标准：不夸大 SO-101、G1、DDS 或 Unitree SDK 经历。

Day 7｜8 月 2 日：安全 SOP 与第一次技术面

Section titled “Day 7｜8 月 2 日：安全 SOP 与第一次技术面”
  • 口述负责人、遥控器、急停、清场和动作边界。
  • 演练 TTS → high wave → release。
  • 回答 duration <= 0 风险。
  • 接受 Claude 的技术和安全追问。

通过标准：三次闭环都完成 release，没有安全否决项。

Day 8｜8 月 3 日：两轮完整模拟

Section titled “Day 8｜8 月 3 日：两轮完整模拟”
  • Dashboard 场景：识别工具、参数和安全顺序。
  • Python/MCP 场景：写请求、解析嵌套结果、处理错误。
  • 接受随机打断并解释当前判断依据。
  • 再抽十行自己的代码解释。

通过标准：两轮均无安全否决项，错误判断有证据。

Day 9｜8 月 4 日：毕业测试

Section titled “Day 9｜8 月 4 日：毕业测试”

连续完成：

  1. 成功闭环：查工具 → 说话 → 单个动作 → release。
  2. 业务错误闭环：用不存在手势，识别嵌套错误并修正。
  3. 网络故障闭环：服务未启动、错误端口或超时中随机一种，按层定位。

同时做到：

  • 90 秒讲清架构与 Mock 边界。
  • 三分钟讲清一次完整排障。
  • 回答“上电前做什么”和“意外运动怎么办”。
  • 不再扩展 C++、Java、完整 ROS 2 或动力学内容。

面试当天

Section titled “面试当天”
  • 只做 20–30 分钟热身：安全 SOP、架构、常见错误。
  • 不改代码、不安装新环境、不测试持续移动。
  • 现场 schema 与负责人指令优先于记忆。
  • 不确定时说明当前证据和下一步验证方法。

一页毕业口述

Section titled “一页毕业口述”

我先确认负责人、遥控器、急停和动作空间，再查看工具 schema。先用 TTS 验证低风险链路，再执行一个预定义上肢动作，等稳定后 release。软件上，请求经 HTTP、JSON-RPC 和 MCP 到 Driver，再通过 ROS 2、DDS、宇树 SDK 到 G1。我亲手练过的是 Client、协议 Mock 和排障；真机后半链路来自公开源码理解。我会用请求 ID、HTTP/RPC 返回、工具结果、Driver 日志和实体状态逐层判断，不把 Mock 当成真机经验。
