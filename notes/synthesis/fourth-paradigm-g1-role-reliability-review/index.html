第四范式 G1 规控实习岗位可靠性核查

第四范式 G1 规控实习岗位可靠性核查

Section titled “第四范式 G1 规控实习岗位可靠性核查”

[!summary] 当前结论 第四范式公司主体和 Phanthy Motus 项目有官方证据，较靠谱；当前这条 BOSS 岗位的具体联系人、签约主体和真实工作内容尚未被官方招聘渠道独立交叉验证。综合判断是：值得去面，具体岗位中等偏靠谱，但不应在核实前无条件相信或签约。

证据分级

Section titled “证据分级”
  • 已证实：存在可直接核对的官方页面、官方仓库或监管披露。
  • 高概率：不同证据相互吻合，但仍缺少直接确认。
  • 未证实：目前没有独立证据，不能当成事实。
  • 风险：存在明显落差或需要在决策前澄清。

五个维度分别判断

Section titled “五个维度分别判断”

1. 公司主体：已证实

Section titled “1. 公司主体：已证实”
  • 第四范式官网提供正式联系方式。
  • 第四范式官方招聘页链接至 Moka 招聘系统。
  • 第四范式投资者关系页和港交所披露检索显示其为港交所上市公司，股票代码 06682。

结论：公司法律与商业主体真实，不属于查不到主体的陌生招聘方。

2. Phanthy Motus 项目：已证实

Section titled “2. Phanthy Motus 项目：已证实”
  • 第四范式官方 GitHub 组织公开并置顶 phanthymotus 和 phanthymotus-driver。
  • 官方 README 描述了 Dashboard、Visual Orchestration、Driver 自动注册和 MCP 工具调用。
  • 官方 Driver README 列出 unitree/g1 和端口 15701，并说明通过 initialize、tools/list、tools/call 发现和调用工具。
  • 仓库在 2026-07-24 至 07-27 仍有更新。

结论：HR 提到的平台和 G1 Driver 不是临时编造的名称，回复内容与官方架构相符。

^[inferred] 但项目较新、社区规模较小，外部使用反馈和长期稳定性尚有限。这不等于项目不真实，只意味着它更像快速迭代中的新平台。

3. BOSS 联系人与具体岗位：未证实

Section titled “3. BOSS 联系人与具体岗位：未证实”

当前没有通过官方招聘页或公开搜索独立找到完全相同的“规控实习生（机械臂）”岗位页面，也没有通过官方域名邮箱或 Moka 日程独立确认当前联系人。

因此尚不能确认：

  • BOSS 联系人是否直接属于目标团队。
  • 实习协议由第四范式本体、子公司还是第三方签署。
  • 北京或上海的具体办公地点。
  • 薪资、考勤、导师和入职流程。
  • “完成即通过”是通过实操轮，还是直接通过全部招聘流程。

搜索不到岗位不是虚假的证明，也可能是渠道岗位、临时岗位或搜索未收录；它只表示目前证据不足。

4. JD 与面试内容：存在风险

Section titled “4. JD 与面试内容：存在风险”

JD 描述偏 Planning & Control 算法、代码重构、跨平台部署、ROS 接口、仿真与真机测试；最新面试却只要求在平台上借助 AI 完成说话和动作编排。

这两者存在明显难度和内容落差，可能有三种解释：

  1. 这只是低门槛实操初筛，入职后再做更深入开发。
  2. 岗位实际更偏 Driver 集成、接口和机器人调试，而“规控算法”标题写得较宽。
  3. 岗位日常更偏平台操作、演示或数据采集，和 JD 中的算法研发不同。

目前无法仅凭 HR 回复判断是哪一种，所以这是必须在面试或 offer 前问清的问题。

5. 对机电学生的价值：高概率有价值，但取决于日常工作

Section titled “5. 对机电学生的价值：高概率有价值，但取决于日常工作”

若实际能参与以下工作，学习价值较高：

  • Driver / MCP 工具和 API 开发。
  • ROS 2 与机器人硬件接口集成。
  • 真机测试、日志分析、Bug 定位和文档。
  • 在不同机器人平台之间迁移工具或 Driver。

若主要工作是：

  • 重复点界面跑演示。
  • 大量数据采集或标注。
  • 按固定脚本操作机器人，几乎不接触代码和调试。

那么对“控制算法/机器人软件工程”简历的价值会显著降低。

正面信号

Section titled “正面信号”
  • HR 对设备、AI、平台、流程和通过标准回答具体。
  • 回复与官方 Dashboard、Driver 注册和工具调用架构一致。
  • 对方提供电脑，不要求自购设备或自行承担部署成本。
  • 到目前为止没有要求收费、押金、培训贷、私下转账、Cookie、验证码或远控私人电脑。

这些信号支持“机会大概率真实”，但不能替代具体岗位核验。

面试前核验

Section titled “面试前核验”
  • 是否收到官方域名邮箱或 Moka 发送的面试日程。
  • 面试地点是否与官方办公信息或可核实团队地点一致。
  • 面试联系人姓名、公司和团队全称是什么。
  • “完成说话+动作即通过”是通过实操轮，还是直接进入 offer。
  • 现场由谁负责机器人安全和急停。

Offer 前核验

Section titled “Offer 前核验”
  • 实习协议的完整签约主体。
  • 实习薪资、发薪方式、考勤和每周到岗要求。
  • 直属导师和团队规模。
  • 六个月日常工作的真实比例。
  • 是否能参与 Driver、API、测试与 Bug 修复。
  • 是否需要做数据采集、演示或重复操作；大约占多少。
  • JD 中 Planning & Control 算法内容具体对应哪些任务。
  • 是否有转正、成果归属、保密和设备责任条款。

建议向 HR 或面试官询问

Section titled “建议向 HR 或面试官询问”

我想进一步了解一下，这个岗位入职后主要是参与 Phanthy Motus Driver、API 和真机测试，还是也会参与机器人规划控制算法？大概各占多少？另外，“完成说话+动作即通过”是指通过实操面试这一轮，还是完成后就进入 offer 流程？

后续实习协议的签约主体、办公地点、薪资考勤和直属导师，可以在进入 offer 流程后通过官方邮件或 Moka 确认吗？

立即停止的红线

Section titled “立即停止的红线”

出现以下任一项，应停止操作并通过官方渠道核实：

  • 收费、押金、培训费、培训贷或私下转账。
  • 要求提供账号 Cookie、验证码或登录凭证。
  • 要求远控私人电脑处理招聘任务。
  • 要求购买指定设备、课程或软件才能面试。
  • 在没有正式流程时索要大量敏感身份材料。
  • 面试地址、签约主体或联系人拒绝提供可核实信息。

最终评级

Section titled “最终评级”
对象当前判断
第四范式公司主体较靠谱，官方与港交所可验证
Phanthy Motus / G1 Driver 项目较靠谱，官方开源且仍在更新
当前面试机会中等偏靠谱，描述与项目架构吻合
当前 BOSS 联系人身份未独立验证
岗位内容与 JD 一致性有明显疑问，需当面澄清
学习价值潜力较高，但取决于是否真正参与 Driver/API/测试

建议：去面试，认真准备，但把它视为一次尚待核验的真实机会，而不是已经确定的 offer。
