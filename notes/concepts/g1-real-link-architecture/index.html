每层负责什么

Section titled “每层负责什么”
层主要责任可观察证据
Client / Dashboard构造请求、展示结果请求 ID、发送内容、客户端异常
HTTP / MCP Driver接收 /mcp 请求并路由方法端口监听、HTTP 状态、顶层 RPC 返回
tts / arm / loco 插件校验工具参数、调用机器人能力工具返回、Driver 日志
ROS 2 / rclpyPython 侧机器人通信框架节点或运行日志
DDS / Unitree SDK与机器人通信初始化状态、网络接口、SDK 返回
G1 实体真正发声和运动姿态、声音、现场安全状态

python3 main.py <networkInterface> 表明 Driver 启动时需要绑定连向机器人的网卡。公开代码中的 ChannelFactoryInitialize(0, iface) 位于 Driver 到 DDS 通信初始化这一层；仅凭这行代码不能声称掌握其内部实现。

为什么必须画完整链路

Section titled “为什么必须画完整链路”

软件返回成功不等于机器人已经安全完成动作。相反，机器人没有动作也不一定是 Python 请求错误：问题可能出在网卡、DDS、SDK、机器人模式或实体状态。

因此，排障要同时保留两类观测点：

  • 软件证据：请求、HTTP、RPC、工具返回、Driver 日志。
  • 物理证据：机器人是否稳定、是否发声、是否完成预期动作。

Mock 覆盖到哪里

Section titled “Mock 覆盖到哪里”

本地协议 Mock 只覆盖 Client、HTTP、JSON-RPC、MCP 和工具分发。它不会模拟 ROS 2、DDS、Unitree SDK、关节运动、平衡和真实物理安全。详见 协议 Mock 与真实机器人的边界。

面试口述

Section titled “面试口述”

客户端把 JSON-RPC 请求通过 HTTP POST 发到 15701 的 /mcp。Driver 解析 method，并在 tools/call 中把参数分发给 tts、arm 或 loco。真机下插件继续通过 ROS 2、rclpy、DDS 和宇树 SDK 与 G1 通信。我的本地练习覆盖前面的协议和分发层，后面的真机链路来自公开源码理解，不会说成亲手操作经验。

自测

Section titled “自测”
  • 能在 90 秒内画出并讲清六层链路。
  • 能区分 Agent Core 15678 与 Driver 15701。
  • 能说明网卡参数为什么属于 Driver/DDS 接入层。
  • 能说出软件成功但实体未动作时还要检查哪些层。
