跨域事实源分层

跨域事实源分层

Section titled “跨域事实源分层”

适用场景：同一批原始材料同时被多个域使用（企业工程记录 × 学校行政材料 × 独立研究工作区 × 知识库沉淀）。此时最大的风险不是「材料不够」，而是派生记录悄悄变成了原件的事实来源。

问题

Section titled “问题”

当一个域既读取外部材料、又产出自己的记录时，会出现三条典型的静默污染路径 ^[inferred]：

  1. 反向覆盖 — 派生条目（工作条目、摘要、简历 bullet）被后续引用时，被当作原始材料本身，原件与派生件的差异消失。
  2. 状态合并 — 「材料可用」「报告里写了」「字段标了 confirmed」被压缩成一个状态，于是「存在」被读成「成立」。
  3. 整目录传递 — 为了让对方域「能参考」，把整个来源目录同步过去，传递范围失去控制。

分层模型

Section titled “分层模型”

以企业实习 + 学校 + 研究三域并存的实例为例 ^[extracted]：

层典型载体该层拥有的唯一事实与其他层的关系
L1 原始来源企业工程技术报告及附件（保留在来源目录）报告与附件中实际记载的内容；作者、版本、核验范围按文件说明被 L2 引用；自身不被改写
L2 派生记录工作条目、活动日志、resume bullet参与过程、完成状态、学习收获（自述性质）从 L1 派生；对外只代表自己的记载
L3 独立工作区研究仓库 / 实验记录 / 主张与准入自有实验、自有测量、自有结论只接收 L1/L2 的引用与经审核摘要

学校行政材料在上述模型里是另一个平行的 L1（学校要求、表格、审批记录），它与企业 L1 之间没有派生关系，只按用途分别引用。同一父目录里行政资料与工程资料混放时（例如 BMF5 目录），必须按具体文件的用途逐份识别，而不是按目录判断 ^[extracted]。

四条规则

Section titled “四条规则”
  1. 单一所有权 — 每个事实只由一层拥有。企业报告的数值、型号、编号由 L1 拥有；「我做了这件事」的陈述由 L2 拥有；研究结论由 L3 拥有。
  2. 不回写原件 — 派生层永远不覆盖来源层。需要版本快照时另记来源、时间与用途，而不是把修正写回原件 ^[extracted]。
  3. 传递最小化 — 跨域只传三件东西：来源引用 + 经审核摘要 + 适用范围。不同步整目录 ^[extracted]。
  4. 升级需协议 — L1/L2 的东西不会因为被 L3 引用就自动变成实验数据；是否成为研究样本取决于对应协议，而不是引用关系本身。

记录契约

Section titled “记录契约”

跨域记录要能回答「这条主张从哪来、谁核过、管到哪、被谁取代过」：

  • 单一 YAML frontmatter（每份记录只有一个头部，避免双头导致字段失效）
  • 证据级别默认 unverified，逐条主张记录：来源、核验者、适用范围、supersedes
  • 状态取值区分 documented（已检查的来源有记载）/ inferred（推断）/ unknown（未核验）

完整契约见 有怡科技材料与 publication-research 的边界契约 · 未公开。

与相邻模式的关系

Section titled “与相邻模式的关系”
  • 个人行政资料来源治理模式 — 那个模式解决「同一批个人资料散落在网页/登录系统/共享盘/邮件」的存放分层（公开 / 私密 / 冷备）；本页解决事实所有权分层。两者可叠加：先分层存放，再分层归属 ^[inferred]。
  • SS2026 备考资料来源边界治理 · 未公开 — 同一原则在备考域的实例：先定义 source eligibility，再生成产物；来源范围修正后必须显式废弃旧产物。
  • 离线历史恢复与证据边界纪律 — 证据不完整时如何输出 truth-bounded 结论。
  • 协议 Mock 与真实机器人的边界 — 边界声明在工程经历陈述中的具体形态。

判定清单

Section titled “判定清单”
  • 这条主张属于哪一层？该层是否有权拥有它？
  • 引用的对象是 L1 原件还是 L2 派生件？两者差异是否已声明？
  • 跨域传递的内容是否只有「引用 + 审核摘要 + 适用范围」？
  • 「可用 / 已记载 / 已核验 / 已生效」是否被拆开记录，而不是压缩成一个字段？
