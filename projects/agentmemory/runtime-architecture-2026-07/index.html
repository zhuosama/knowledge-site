AgentMemory 运行架构与功能对话治理

AgentMemory 运行架构与功能对话治理

Section titled “AgentMemory 运行架构与功能对话治理”

[!important] 权威边界 共享 AgentMemory 保存规则、证据、功能事件和经审核知识；Codex、Claude Code、Hermes、Pi 的私有 session、token、缓存和完整 transcript 不进入共享仓库。

启动链

Section titled “启动链”

每个新任务和恢复的旧任务都读取当前 startup digest，再按项目加载必要上下文。SOP 更新后必须重建摘要；摘要落后时健康检查应报告漂移。

功能对话

Section titled “功能对话”

功能 ID 使用 F-<端点代理>-<YYMMDD>-<序号>。任务标题采用：

<简介> [<功能 ID>][<阶段>]

例如：历史对话整理与归档 [F-WC-260819-01][OPS]。

阶段包括 DISCUSS、IMPLEMENT、STUDY、OPS、REVIEW 和 BUG-nn。同一功能跨阶段时保留功能 ID，目标、产物或来源边界变化时才创建新 ID。

Agent 来源码

Section titled “Agent 来源码”
  • WC / MC：Windows / Mac Codex
  • WCC / MCC：Windows / Mac Claude Code
  • WP / MP：Windows / Mac Pi
  • MH：Mac Hermes

来源码记录功能首次创建位置，后续交接不改编号。

隐私与历史审计

Section titled “隐私与历史审计”

共享 workstreams/events.jsonl 不保存 raw prompt、完整 transcript、凭据或 thread/session ID。精确任务映射和脱敏历史审计结果只保存在各端点 Git 忽略目录。历史任务自动化仅处理高置信映射；歧义项必须进入人工复核。

严重问题闭环

Section titled “严重问题闭环”

S0/S1 且可跨任务复现的 workflow incident 依次进入 incident、ATTENTION、SOP proposal、curator 审核、startup digest 重建、状态刷新和验证。S2/S3 不得自动升级为全局规则。

跨端同步与权限

Section titled “跨端同步与权限”

[!warning] Syncthing 不是合并权威 Syncthing 负责低延迟传输工作文件；Git 负责审查、提交和历史。两端未追平时不得同时编辑同一个共享文件。

  • Windows 根目录：[private memory root]
  • Mac 根目录：[private local path]
  • 两端版本保护：90 天 staggered versioning，版本目录在 AgentMemory 之外
  • 权限/ownership/xattrs：不通过 Syncthing 传输；Git 管理可执行位
  • endpoint-agent 只写自己的 episodes/imports，curator 独占 curated 晋升
  • 完成门禁：本地 idle/need=0，peer completion=100% 或记录有意 ignore 边界

稳定契约：specs/workflow/cross-endpoint-sync-contract.md。
