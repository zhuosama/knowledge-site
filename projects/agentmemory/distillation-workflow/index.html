AgentMemory 双层蒸馏工作流设计

AgentMemory 双层蒸馏工作流设计

Section titled “AgentMemory 双层蒸馏工作流设计”

问题

Section titled “问题”

AgentMemory 需要一个可重复运行的蒸馏流程，它不能把 agent 运行规则、可复用知识和具体项目经验混进同一个未分化的 proposal 流。

核心原则

Section titled “核心原则”

有界证据集（Bounded Evidence）

Section titled “有界证据集（Bounded Evidence）”

自动记忆蒸馏应该保持窄范围。有用的信号是：

  • 被明确分配的任务文件
  • 必需的启动/路由/模板文件
  • 一个小的、有上限的证据集

不应该扫描每个被接受的 proposal 或原始 workspace 文件。^[extracted]

先写报告，再验证（Output-First）

Section titled “先写报告，再验证（Output-First）”

蒸馏执行顺序：

  1. 读取任务中显式指定的输出路径
  2. 先写出报告
  3. 创建一条 agent-rule proposal 和一条 knowledge proposal
  4. curated memory 留给后续 curator pass 处理 ^[inferred]

“什么有用的都没找到”是一个可报告的结果，不是应该制造填充记忆的借口。^[extracted]

双分支 Proposal 模型

Section titled “双分支 Proposal 模型”

每条蒸馏产出的 artifact 走两个分支之一：

  • agent-rules 分支：运行规则 -> proposals/agent-rules/pending/
  • knowledge 分支：知识和经验 -> proposals/knowledge/pending/

两个分支的 proposal 格式不同，验证门槛不同，curator 处理节奏也不同。^[inferred]

System Trial 验证

Section titled “System Trial 验证”

一次系统级 trial 的执行路径：

  1. 使用有上限的证据集
  2. 保留任务中的显式输出路径
  3. 先写报告
  4. 产出分支特定的 artifact 供 curator 审查
  5. 验证作为最终确认步骤，在持久化输出已存在之后进行

产物清单

Section titled “产物清单”

Trial 产出：

  • 一条 agent-rule proposal（蒸馏 artifact 排序规则）
  • 一条 knowledge proposal（知识声明与经验卡分离的规则）
  • 一张项目经验卡（AgentMemory 蒸馏系统 trial）
  • 一份 trial 周期的蒸馏报告
  • 一条 Windows Codex episode 观察记录 ^[extracted]

可复用模式

Section titled “可复用模式”

对可重复的知识系统自动化：将操作规则、可复用经验、用户面向的经验叙述分离到不同的 artifact。在创建经验卡之前要求明确的证据类，验证仅在持久化输出存在后进行。

避免事项

Section titled “避免事项”
  • 不要扫描无关的 accepted proposals
  • 不要导入运行时缓存
  • 不要写入另一个 endpoint-agent 的 raw 路径
  • 不要让窄蒸馏任务把 curated memory 不经审查直接修改 ^[extracted]
