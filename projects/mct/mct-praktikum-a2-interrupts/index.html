A2 Interrupts 讲解

A2 Interrupts 讲解

Section titled “A2 Interrupts 讲解”

任务目标

Section titled “任务目标”

A2 的目标不是重写整个交通灯逻辑，而是把 S0 的触发方式 从 A1 的 polling 改成 interrupt。

换句话说：

  • 交通灯时序基本不变
  • 变化的是“按键被发现”的方式

前置任务已知内容

Section titled “前置任务已知内容”

默认你已经理解 A1 的以下内容：

  • GPIO 输出与输入的基本配置
  • active-low LED
  • pull-up 输入
  • LEDs_set() 的作用
  • 交通灯业务时序
  • polling 的基本思路

因此 A2 不再重复长篇解释这些内容，而只解释新出现的机制。

本任务新增的思路

Section titled “本任务新增的思路”

1. 从 polling 变成 interrupt-driven

Section titled “1. 从 polling 变成 interrupt-driven”

A1 的思路是：主循环不断主动检查按钮。
A2 的思路是：按钮一按下，就由硬件触发中断，通知 CPU“有事件发生了”。

2. ISR 不做完整业务，只做最小动作

Section titled “2. ISR 不做完整业务，只做最小动作”

A2 没有把整个交通灯序列写进 ISR，而是采用了更好的分工：

  • ISR 里只把 g_button_pressed 设为 1
  • 主循环看到 flag 后，再执行完整序列

这是一个非常重要的结构设计点。

3. 业务逻辑和触发机制被分开

Section titled “3. 业务逻辑和触发机制被分开”

A1 中，“检测到按键”和“开始跑序列”在同一段主循环里完成。
A2 中，触发由中断完成，业务执行仍由主循环完成，所以结构更清楚。

SYSCFG + EXTI

Section titled “SYSCFG + EXTI”

这一段是 A2 最重要的新内容，因为它决定“PB0 按键为什么会触发中断”。

1. SYSCFG 是什么

Section titled “1. SYSCFG 是什么”

SYSCFG 是 System Configuration Controller，可以理解为“系统级配置控制器”。
在 A2 里，它最重要的作用是：

  • 把某一条 EXTI 中断线映射到某个 GPIO 端口

因为 STM32 里不是所有 0 号引脚都天然连到同一条中断来源上，而是要通过 SYSCFG 明确指定：

  • EXTI0 监听的是 PA0 还是 PB0 还是 PC0

A2 里 S0 接在 PB0，所以必须明确把 EXTI0 映射到 Port B。

2. SYSCFG->EXTICR[0] 这两句怎么理解

Section titled “2. SYSCFG->EXTICR[0] 这两句怎么理解”

先解释寄存器结构：

  • EXTICR[0] 负责 EXTI0 到 EXTI3
  • 每条 EXTI 线占 4 bit
  • 对 EXTI0 来说，使用的是 bit [3:0]

这些 bit 的值表示中断线来自哪个端口：

bit[3:0] 的值表示监听哪个端口
0000PA
0001PB
0010PC

所以这两句连起来的意思是：

  1. 先把 EXTI0 对应的 4 个 bit 清零
  2. 再写入 0001
  3. 于是 EXTI0 就改为监听 PB0

可以把它直接口头翻译成：

“把 EXTI0 的来源从默认端口改成 Port B，所以它现在对应的是 PB0。”

3. IMR1、FTSR1、RTSR1 各自做什么

Section titled “3. IMR1、FTSR1、RTSR1 各自做什么”

这三个都是 EXTI 外设的关键寄存器：

寄存器作用A2 中的含义
IMR1中断屏蔽寄存器允许 EXTI0 的中断请求送出去
FTSR1下降沿触发寄存器按下按钮时触发
RTSR1上升沿触发寄存器松开按钮时是否触发

逐句说：

  • EXTI->IMR1 |= (1 << 0); 把 EXTI0 的 interrupt mask 打开，不再屏蔽这条中断线
  • EXTI->FTSR1 |= (1 << 0); 允许下降沿触发 fallende Flanke
  • EXTI->RTSR1 &= ~(1 << 0); 禁止上升沿触发 steigende Flanke

为什么只选下降沿？

因为 S0 的硬件逻辑是：

  • 没按下：PB0 = High
  • 按下：PB0 = Low

所以“按下”对应的是 High -> Low，也就是下降沿。

  • NVIC_SetPriority(EXTI0_IRQn, 1); 设置 EXTI0 的优先级
  • NVIC_ClearPendingIRQ(EXTI0_IRQn); 把可能残留的 pending 状态先清掉，防止程序一启动就误进中断

5. 这一整段配置可以怎么整体理解

你可以把这一段直接概括成一句话：

“把 PB0 接到 EXTI0，只允许按下时的下降沿触发，然后在 NVIC 里正式打开这个中断。”

GPIOA->MODER = (GPIOA->MODER & 0xFFFFFF00) | 0x44; 这句是什么意思

Section titled “GPIOA->MODER = (GPIOA->MODER & 0xFFFFFF00) | 0x44; 这句是什么意思”

这句代码不在主流程里，而是在 A2_Interrupts_it.c 的 ISR_default() 中。
ISR_default() 是一个“兜底中断处理函数”，当程序误进入了没有专门处理的中断时，就执行这段代码点亮板子上的错误提示灯。

这一句的作用是：把 PA0..PA3 配成输出模式，用来点亮错误指示灯。

拆开看：

  • GPIOA->MODER & 0xFFFFFF00 把低 8 位清零，也就是先清掉 PA0..PA3 的模式位
  • | 0x44 再把需要的位置写成 0100 0100

0x44 = 0b0100_0100，对应：

  • PA0: 00
  • PA1: 01
  • PA2: 00
  • PA3: 01

也就是说这里只把 PA1 和 PA3 配成输出。

代码总体流程

Section titled “代码总体流程”

1. 初始化阶段

Section titled “1. 初始化阶段”

GPIO_init() 除了保留 A1 的 GPIO 配置外，又增加了三部分：

  1. 开启 SYSCFG 时钟
  2. 把 EXTI0 映射到 PB0
  3. 配置 EXTI 和 NVIC

如果你向老师讲这里，可以直接按下面顺序说：

  1. SYSCFG->EXTICR[0] 负责决定 EXTI0 接哪一个 port
  2. EXTI->IMR1 打开中断线
  3. EXTI->FTSR1 选择下降沿触发
  4. EXTI->RTSR1 关闭上升沿触发
  5. NVIC_* 三句负责把这个中断正式交给 CPU

关键改动总结

Section titled “关键改动总结”

相对于 A1，A2 的关键改动可以概括为：

  1. 新增全局共享 flag g_button_pressed
  2. 主循环从“直接轮询 PB0”改成“等待 flag 被 ISR 置位”
  3. 在 GPIO_init() 中新增 SYSCFG / EXTI / NVIC 配置
  4. 在 A2_Interrupts_it.c 中实现 ISR_S0()
  5. 在中断向量表中把 EXTI0 对应入口改成 ISR_S0

最重要的一句话总结：

A2 改的是“输入触发机制”，不是“交通灯业务行为”。

老师可能追问的问题与回答

Section titled “老师可能追问的问题与回答”

为什么不用 polling 了？

Section titled “为什么不用 polling 了？”

因为 A2 的目标就是学习外部中断，让硬件事件主动通知 CPU，而不是主循环不断检查。

为什么 ISR 里不直接执行整个交通灯流程？

Section titled “为什么 ISR 里不直接执行整个交通灯流程？”

因为 ISR 应该尽量短。完整流程很长，放在 ISR 里会让中断处理时间过长，也不利于结构分层。

为什么 g_button_pressed 必须是 volatile？

Section titled “为什么 g_button_pressed 必须是 volatile？”

因为它会在 ISR 中被修改，主循环和 ISR 共享同一个变量。

为什么要清 EXTI->PR1？

Section titled “为什么要清 EXTI->PR1？”

因为这是 pending bit。如果不清，中断请求状态还在，CPU 可能立刻再次进 ISR。

为什么选下降沿触发？

Section titled “为什么选下降沿触发？”

因为按钮按下时 PB0 从 High 变 Low。这个边沿才代表“真正按下”。

A2 和 A1 的业务效果有区别吗？

Section titled “A2 和 A1 的业务效果有区别吗？”

基本没有。两题的交通灯序列一样，区别在于 A1 用 polling 检测触发，A2 用 interrupt 检测触发。
