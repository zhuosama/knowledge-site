1U、移位和裸数字

Section titled “1U、移位和裸数字”

1U 是什么

Section titled “1U 是什么”

1U 表示一个值为 1 的 unsigned int，也就是无符号整数 1。

寄存器通常按无符号位字段理解，所以 STM32 代码里常用 1U 而不是普通的 1。这样可以明确表达：这里不是数学上的数字 1，而是要生成一个 bit mask。

什么是裸数字

Section titled “什么是裸数字”

“裸数字”指代码直接写数字或位移，而不是使用有名字的宏。

两句通常生成同样的机器效果，但可读性不同：

  • 裸数字告诉你“操作 bit 0”
  • 宏名告诉你“打开 EXTI interrupt mask line 0”

因此在学习寄存器时可以先看裸数字理解 bit，再用宏名理解语义。

关键位分别在干什么

Section titled “关键位分别在干什么”
  • UG = Update Generation
  • 作用：强制产生一次更新事件，让预分频和重装值立即装载
  • UIE = Update Interrupt Enable
  • 作用：允许 update event 发出中断请求
  • UIF = Update Interrupt Flag
  • 作用：清除“刚刚发生过 update event”的标志
  • CEN = Counter Enable
  • 作用：启动定时器计数

中断号 / 向量表 / ISR 派单机制

Section titled “中断号 / 向量表 / ISR 派单机制”

它是什么

Section titled “它是什么”

STM32 上”哪个外设触发中断 → CPU 跳到哪个函数”，由三层东西决定：

  1. IRQ 号（中断号）：每个外设/事件源有一个唯一编号，由芯片硬件钉死。
  2. 向量表：一张函数指针数组，存放在 Flash 的 .isr_vector section。CPU 上电后从这张表的固定偏移读地址。
  3. NVIC（Nested Vectored Interrupt Controller）：硬件路由器。外设按下”门铃”时，NVIC 根据 IRQ 号查向量表，把控制权交给对应函数。

CPU 不会”广播”中断给所有 ISR——派单是精准点对点的。

为什么在任务中出现

Section titled “为什么在任务中出现”
  • A2：EXTI0 → ISR_S0（一个中断源）
  • A3：EXTI0 + TIM6 各自一条线（两个中断源）
  • A4 lowpower：EXTI0 + EXTI4 + TIM6 + TIM7 共四条独立线（四个中断源），都要在向量表里各占一个位置

学生最容易踩的坑：以为”TIM7 溢出会触发 ISR_Timer”——其实 TIM7 走自己的 55 号通道，跟 TIM6 的 54 号通道完全独立。

关键不变量

Section titled “关键不变量”
  • 向量表槽位 ↔ IRQ 号：写死映射，由硬件和编译时决定
  • IRQ 号 ↔ 外设：写死映射，芯片厂决定

EXTI / NVIC / Pending Bit

Section titled “EXTI / NVIC / Pending Bit”

它是什么

Section titled “它是什么”
  • EXTI：外部中断控制器，负责“哪个引脚事件会触发中断”
  • NVIC：中断控制器，负责“这个中断是否允许进入 CPU”
  • Pending Bit：表示“某个中断请求已经挂起，等待处理或刚刚发生”

为什么在任务中出现

Section titled “为什么在任务中出现”

A2 要把 S0 从轮询改成中断触发，所以必须完成三步：

  1. 把 PB0 映射到 EXTI0
  2. 在 EXTI 中打开中断并选择下降沿触发
  3. 在 NVIC 中真正使能 EXTI0_IRQn

中断处理结束后还要清 pending bit，否则会反复进入 ISR。

关键配置语句怎么逐句理解

Section titled “关键配置语句怎么逐句理解”
  • 清掉 bit [3:0]
  • 再写入 0001
  • 表示 EXTI0 的来源改成 Port B
  • 打开 EXTI0 的 interrupt mask
  • 没有这句就不会真正产生中断请求
  • 打开下降沿触发
  • 关闭上升沿触发
  • 因为 S0 按下时是 High -> Low
  • 设优先级
  • 清旧 pending
  • 使能中断

这组配置的逻辑顺序

Section titled “这组配置的逻辑顺序”

可以把它理解成一句完整的话：

“把 PB0 接到 EXTI0，上升沿不要，下降沿要，允许 EXTI0 发出请求，再允许 CPU 接收这个请求。”

用主程序视角重新串起来

Section titled “用主程序视角重新串起来”

如果你觉得这组寄存器太散，可以按“信号从按钮走到 CPU”的顺序记：

  1. SYSCFG->EXTICR[0] 决定 EXTI0 到底接 PA0、PB0 还是别的 0 号引脚
  2. EXTI->IMR1 决定这条线是不是允许发送中断请求
  3. EXTI->FTSR1 / RTSR1 决定什么边沿会触发
  4. NVIC_* 决定 CPU 是否真正接收并处理中断

这样就不是死记寄存器名，而是记住“按钮事件走到中断函数要经过哪几层”。

__attribute__((weak)) 弱符号

Section titled “__attribute__((weak)) 弱符号”

它是什么

Section titled “它是什么”

GCC 扩展，加在函数定义前：

weak 不影响函数本身的代码，只影响链接器的优先级规则：

  • 普通定义 = 强符号，重复会报 multiple definition 错
  • weak 定义 = 弱符号，被任何同名强符号 override，自己被丢弃

为什么在任务中出现

Section titled “为什么在任务中出现”

A4 工程里主版本 A4_Entprellen.c 和低功耗版本 A4_Entprellen_lowpower.c 共用同一份 A4_Entprellen_it.c。it.c 的中断向量表静态引用 ISR_DebounceTimer，但主版本不实现它——直接链接会失败。

解决方法：在 it.c 给一个 __weak 的空 ISR_DebounceTimer 作 fallback。

  • 链接 lowpower：lowpower.c 提供强符号 → 顶掉 weak fallback
  • 链接主版本：找不到强符号 → 用 weak fallback（永远不执行，因为主版本不开 TIM7）
