A3 Timer 低功耗变体讲解

A3 Timer 低功耗变体讲解

Section titled “A3 Timer 低功耗变体讲解”

本页是 A3 Timer 讲解 的延伸笔记。基础 A3 内容（TIM6 工作原理、状态机思路、volatile、__WFI() 等）默认已掌握，这里只讲为什么要再优化、怎么优化、改了哪些代码。

问题背景

Section titled “问题背景”

课堂讨论中教授指出：原 A3 方案虽然把 busy-wait 换成 TIM6，但每毫秒仍要唤醒 CPU 一次，并不真正省电。

具体到原代码 A3_Timer.c：

  • TIM6 配成 1 kHz tick，每 1 ms 触发 update interrupt
  • ISR 里 99% 的情况只是把 g_state_timeout_ms 减 1
  • 即使在 TRAFFIC_STATE_IDLE_GREEN（按下按钮前）TIM6 也在跑，每 1 ms 都唤醒一次 CPU 然后立刻 return

本任务新增的思路

Section titled “本任务新增的思路”

1. 等待方式的两种优化方向

Section titled “1. 等待方式的两种优化方向”
方向思路节省点
方案一：IDLE 时停 timer进入 TRAFFIC_STATE_IDLE_GREEN 时清 CR1.CEN，CPU 只能被 EXTI0 唤醒等按钮期间 0 次唤醒
方案二：每状态重配 ARR进入新状态时把 ARR 设成该状态的总时长，TIM6 只在阶段结束时响一次每阶段 1 次唤醒

两个方向互不冲突，可以叠加：IDLE 用方案一，其他阶段用方案二。行人阶段是例外——蓝灯必须每 500 ms 翻转一次，所以这一阶段保留周期性 ISR，但周期从 1 ms 拉长到 500 ms。

2. One-Pulse Mode 是方案二的关键

Section titled “2. One-Pulse Mode 是方案二的关键”

STM32 通用 timer（含 TIM6）有一个控制位 CR1.OPM（One-Pulse Mode）：

  • OPM = 0（默认）：到了 ARR 自动重装、继续计数，周期性产生 update event
  • OPM = 1：到了 ARR 产生一次 update event 后自动清掉 CEN，timer 停下来不再计数

OPM 让我们不需要在 ISR 里手动停 timer——硬件自己停。每次进入新状态：

  1. 写新的 ARR
  2. 设 OPM = 1
  3. 设 CEN = 1 启动

阶段结束时：

  1. 硬件触发一次 update interrupt
  2. 硬件自动清 CEN
  3. ISR 里直接 Traffic_advance() 进入下一状态（下一状态再重新配 ARR/CEN）

本任务新增的语法 / 寄存器 / 机制

Section titled “本任务新增的语法 / 寄存器 / 机制”

TIM_CR1_OPM —— One-Pulse Mode 控制位

Section titled “TIM_CR1_OPM —— One-Pulse Mode 控制位”

CMSIS 头文件里定义为 (0x1UL << 3)，即 CR1 的 bit 3。设置后：

  • 计数器到达 ARR → 产生 update event → 自动清 CEN
  • 不影响 update interrupt 的产生（UIE 仍正常工作）
  • 不影响 PSC/ARR 的自动重装值（ARR 还是会被装回 CNT，只是 CEN 没了）

OPM 不需要 ISR 配合就能停，特别适合「一次性延时」语义。

关键改动总结

Section titled “关键改动总结”

把新文件 A3_Timer_lowpower.c 和原文件 A3_Timer.c 对比，核心改动是 6 点：

  1. PSC 从 1599 改成 15999：直接拿到 1 kHz 计数时钟，让 ARR 单位 = 1 ms
  2. Timer_init() 不再启动 timer：只配寄存器，不写 CEN
  3. 新增 Timer_stop() / Timer_start_oneshot() / Timer_start_periodic()：把 timer 的「停 / 一次性启动 / 周期启动」抽成三个明确动作
  4. Traffic_state_enter() 每个分支调用合适的 Timer_start_*：IDLE 调 stop，行人调 periodic，其他调 oneshot
  5. 删除 g_state_timeout_ms 和 g_blue_toggle_ms：毫秒级计数交给硬件 ARR，软件不再每 ms 自减
  6. 新增 g_pedestrian_toggles_left：行人阶段用「数 30 次翻转」代替「数 15000 次毫秒」

一句话总结：

原 A3 是「timer 提供节拍 + 软件计数毫秒」，低功耗版本是「timer 直接定义阶段时长 + CPU 只在阶段结束时醒」。

老师可能追问的问题与回答

Section titled “老师可能追问的问题与回答”

为什么不直接用 LPTIM + Stop mode 进一步省电？

Section titled “为什么不直接用 LPTIM + Stop mode 进一步省电？”

LPTIM 可以在 STM32G4 的 Stop mode 下运行，时钟源用 LSI（32 kHz）或 LSE，确实能再省一档电。但代价是：

  • 切换 LPTIM 需要重新设计时钟树和唤醒逻辑
  • Stop mode 下 GPIO retention 和 EXTI 配置规则更严
  • 调试器在 Stop mode 下会断连，开发更难

本变体先用 TIM6 + Sleep mode 把唤醒次数从 29 000 降到 35，已经把最大头的浪费拿掉。LPTIM + Stop 是「再优化一档」的方案，属于工程权衡。

为什么 PEDESTRIAN 不用 OPM + 软件计 30 次重启？

Section titled “为什么 PEDESTRIAN 不用 OPM + 软件计 30 次重启？”

理论上可以：每 500 ms OPM 触发一次，ISR 里翻蓝灯然后再 Timer_start_oneshot(500)。但这样：

  • 每次都要重写 ARR/CR1，开销略大
  • ISR 路径变长，反而稍微费电

周期模式（OPM=0）让硬件自己重装、自己继续计数，ISR 只负责翻 LED 和数次数。代码也更短。

Timer_start_oneshot() 里为什么要先 CR1 &= ~CEN 再写 ARR？

Section titled “Timer_start_oneshot() 里为什么要先 CR1 &= ~CEN 再写 ARR？”

防御性写法。如果当前 timer 还在跑（理论上不会，因为 OPM 自动停 + 上一阶段 ISR 已经走完），先停一下确保 CNT/ARR/EGR 写入时计数器是静止的，避免极端时序下出现「半装载」。代价只是几条空写，性能可忽略。

为什么不直接关 RCC 里的 TIM6EN 来省更多电？

Section titled “为什么不直接关 RCC 里的 TIM6EN 来省更多电？”

可以再加一档优化：Timer_stop() 里追加 RCC->APB1ENR1 &= ~RCC_APB1ENR1_TIM6EN，start 时再开。但 16 MHz 的 STM32G4 上单个外设时钟门的功耗收益很小（μA 级别），增加的代码复杂度（每次 start 要重新跑一遍 PSC/ARR 配置）不划算。如果换成 LPTIM + Stop mode 重构则另当别论。

OPM=1 让硬件清 CEN，那么 ISR 里我还需要再清一遍吗？

Section titled “OPM=1 让硬件清 CEN，那么 ISR 里我还需要再清一遍吗？”

不需要。OPM 触发的清 CEN 是原子的，ISR 进来的时候 CEN 已经是 0。ISR 里如果再写一次 CR1 &= ~CEN 是无害的但多余。

一次序列只有 35 次唤醒，主程序大部分时间在干嘛？

Section titled “一次序列只有 35 次唤醒，主程序大部分时间在干嘛？”

进入 __WFI() 后 CPU 进入 Sleep mode：

  • CPU 时钟停（节能主项）
  • Flash 时钟停
  • AHB/APB 外设按各自配置可继续运行（TIM6 必须继续，否则 ARR 计不到）
  • SysTick、所有未屏蔽中断仍能唤醒 CPU

唤醒延迟约几个时钟周期（< 1 μs），ISR 跑完几条指令再 __WFI() 回去。29 秒序列里 CPU 真正运行的时间可能不到几百微秒。

这段代码上板时序还和原版一样吗？

Section titled “这段代码上板时序还和原版一样吗？”

是的。每个阶段的时长由 ARR 直接定义：

  • ARR=9999, PSC=15999, f_clk=16 MHz → (9999+1)*(15999+1)/16e6 = 10.000 s（绿灯）
  • ARR=499, PSC=15999 → 0.500 s（蓝灯翻转）

精度由硬件晶振决定，软件层面无累积漂移。

本变体中最容易看不懂的代码逐句解释

Section titled “本变体中最容易看不懂的代码逐句解释”

1. Timer_start_oneshot() 的 7 步配置

Section titled “1. Timer_start_oneshot() 的 7 步配置”

逐句对应硬件动作：

  1. CR1 &= ~CEN — 停 timer，让接下来的写不被并发计数干扰
  2. CNT = 0 — 计数器归零（不归零的话从上次残值继续，时长会偏短）
  3. ARR = ms-1 — 设这一阶段总长（减 1 是因为计数从 0 开始）
  4. EGR = UG — 让 PSC/ARR 立即装入影子寄存器；副作用是 UIF=1
  5. SR = 0 — 清 UIF（如果不清，下一句开 CEN 后立刻进 ISR）
  6. NVIC_ClearPendingIRQ — NVIC 层也清一遍，防御性
  7. CR1 |= OPM 然后 CR1 |= CEN — 选一次性模式 + 启动

2. (ms > 0U) ? (uint16_t)(ms - 1U) : 0U 为什么要判 0

Section titled “2. (ms > 0U) ? (uint16_t)(ms - 1U) : 0U 为什么要判 0”

如果调用方传 ms = 0，ms - 1 在 uint16_t 上会下溢成 65535，timer 反而跑 65 秒。三目表达式把 0 输入挡在外面（虽然本代码里所有 WAIT_*_MS 宏都 ≥ 1000，传 0 不会发生，但这是防御性写法）。

3. ISR 里为什么要先判 PEDESTRIAN

Section titled “3. ISR 里为什么要先判 PEDESTRIAN”

行人阶段是唯一需要在阶段中途处理事情的状态（蓝灯翻转）。其他所有 OPM 阶段进 ISR 都意味着「该阶段刚刚结束」，直接 Traffic_advance() 切下一态即可。两类语义完全不同，必须分支处理。

4. 为什么 Traffic_state_enter() 每次都先把 g_blue_led_on 设回 0

Section titled “4. 为什么 Traffic_state_enter() 每次都先把 g_blue_led_on 设回 0”

防御性「清场」：避免上个 PEDESTRIAN 阶段结束时蓝灯停在某个状态，污染下一阶段。即使下一阶段不显示蓝灯，把变量归零也能保证下次再进 PEDESTRIAN 时初始值确定。

如何切换两个版本编译

Section titled “如何切换两个版本编译”

工程里同时存在 A3_Timer.c 和 A3_Timer_lowpower.c 时，会因为重复符号（main、ISR_S0、ISR_Timer 等）链接失败。两种处理方式：

  1. 手动 exclude from build：在 STM32CubeIDE 里右键想禁用的那个 .c → Resource Configurations → Exclude from Build → 勾上当前 build configuration
  2. 改 makefile：在 Debug/Src/subdir.mk 里把对应 .o 从 OBJS 里删掉

老师抽查时如果切换演示，记得提前确认链接通过。
