A1 GPIO 与 Polling 讲解

A1 GPIO 与 Polling 讲解

Section titled “A1 GPIO 与 Polling 讲解”

任务目标

Section titled “任务目标”

A1 的目标是：在 STefi Light 板上实现一个完整的交通灯流程。

  • 默认状态下车灯为绿灯
  • 按下 S0 后开始固定时序
  • 蓝灯表示行人通行
  • 长按或不松手不能导致序列反复触发

这一题的核心不在“算法复杂”，而在于第一次完整把：

  • GPIO 输出
  • GPIO 输入
  • 硬件电平逻辑
  • 轮询式控制流程

串起来。

前置任务已知内容

Section titled “前置任务已知内容”

A1 是 Praktikum 的起点，因此默认只假设你会最基础的 C 阅读，不假设你已经懂：

  • STM32 寄存器配置
  • GPIO 时钟使能
  • active-low
  • pull-up
  • polling

这些内容在 A1 里都是新知识。

本任务新增的思路

Section titled “本任务新增的思路”

1. 先理解硬件，再写代码

Section titled “1. 先理解硬件，再写代码”

这题不能先从 if 和 while 开始看，而要先看引脚：

  • PA0..PA3 控制 LED
  • PB0 读取按键 S0

代码是在“描述引脚应该怎么工作”。

2. 输出和输入是两类不同问题

Section titled “2. 输出和输入是两类不同问题”
  • LED 是输出问题：我要控制某个 pin 输出高低电平
  • 按键是输入问题：我要读取 pin 当前状态

所以同样是 GPIO，但配置方式不同。

3. A1 用的是 polling，不是 interrupt

Section titled “3. A1 用的是 polling，不是 interrupt”

主循环一直自己检查 GPIOB->IDR，看看按键有没有按下。
CPU 主动问输入状态，这就叫 polling。

4. 业务流程和输入触发耦合在一起

Section titled “4. 业务流程和输入触发耦合在一起”

A1 中，一旦检测到按键，主循环立刻进入整个交通灯序列。
也就是说，输入检测和业务启动是在同一个控制流里完成的。

MODER

Section titled “MODER”

MODER 决定某个 pin 是输入、输出还是别的模式。
A1 里：

  • PA0..PA3 被设成输出
  • PB0 被设成输入

PUPDR

Section titled “PUPDR”

PUPDR 用来设置 pull-up / pull-down。
PB0 开了 pull-up，这样未按下时稳定为高电平，按下时接地变低电平。

IDR 和 ODR

Section titled “IDR 和 ODR”
  • IDR 读输入
  • ODR 写输出

这是 A1 第一次明确建立“读输入寄存器”和“写输出寄存器”的区别。

位运算

Section titled “位运算”

A1 里很多寄存器不是整体写，而是先清后设。

Busy-Wait

Section titled “Busy-Wait”

delay() 通过双重循环和 __asm("NOP") 实现空转延时。
这是一种简单但占 CPU 的延时方式。

main() 先做三件事：

  1. __disable_irq()
  2. GPIO_init()
  3. __enable_irq()

虽然 A1 不用按键中断，但初始化阶段先关全局中断是一种稳妥写法，避免配置过程中被打断。

关键改动总结

Section titled “关键改动总结”

相对于模板，A1 的核心改动可以概括为四块：

  1. 完成 GPIO_init()，把 PA0..PA3 配成输出、PB0 配成输入并打开 pull-up
  2. 写出 LEDs_set()，统一处理 active-low 的 LED 点亮逻辑
  3. 在主循环中通过 polling 检测 S0，并执行完整交通灯流程
  4. 在流程尾部补上“等待按键松手”，防止长按重复触发

老师可能追问的问题与回答

Section titled “老师可能追问的问题与回答”

为什么 LED 是写 0 才亮？

Section titled “为什么 LED 是写 0 才亮？”

因为板子的 LED 是 active-low 接法，pin 拉低时导通。

为什么 PB0 要开 pull-up？

Section titled “为什么 PB0 要开 pull-up？”

因为按钮未按下时如果输入悬空，读值不稳定。开 pull-up 后，未按下稳定为高电平。

为什么 A1 用 polling？

Section titled “为什么 A1 用 polling？”

因为 A1 的目标就是先熟悉 GPIO 输入输出和最基本的控制流程，还没有进入中断机制。

为什么最后要等待松手？

Section titled “为什么最后要等待松手？”

为了避免长按导致序列刚结束就立刻再次触发。

delay() 为什么不是好方案？

Section titled “delay() 为什么不是好方案？”

因为它让 CPU 一直空转，占用处理器时间，后面更好的方案会用 timer。
